## Tic JSON (as in the spec)
`{ name, kind: "loop"|"oneshot", duration | cycle, still, keys[{t, pose, face?, ease?, hold?}], props[{id, at, to, pos?, rot?}], emit[{at, type, from}] }`.
- `pose` only holds `KEYS` names; a missing key = the **base loop's** value at that moment (layering). Keys are sparse per key AND per channel: a channel is interpolated between the keys that mention it; before its first / after its last mention it follows the base loop (so `{}` at t=0 and t=duration means "base", exactly the bow in the spec).
- `ease` applies to the segment ending at that key (`in|out|inout|linear`, default `inout`); `hold: true` freezes the previous key's value until this key's time.
- `expr` / `mouth` are never in `pose`; `face` (a FACE name) replaces them. Validation in `registerTic`: unknown pose key / face / prop socket / non-monotonic `t` throws a readable error (editor shows it, game console.warns and skips the tic).
- Props socket table (`handR handL chest head back home`) → `ch.arms[1].hand`, `ch.arms[0].hand`, `ch.spine`, `ch.head`, `ch.spine` (back offsets), and `home` = `moveHome(m, ch[id + 'Home'])`. `to:"home"` and the `skip` hook use the same code path as today's `moveHome`.
- `emit`: `anim.emit(type, pivotByName(from))` once when time passes `at` (flag set kept in `this.jt`).

## Hooking into ChibiAnimator without changing code tics
- `registerTic(json, { force })` in chibi.js: stores `JSON_TICS[name]`; then
  - `oneshot`: sets `ONESHOT[name] = duration` and pushes to `STILL` if `still`, and defines `ChibiAnimator.prototype['_' + name]` = `function (p, t) { return jsonPose.call(this, JSON_TICS[name], p, t) }`. The existing dispatch (`this['_' + this.one](pose, oneT)`) needs no edit.
  - `loop`: `LOOPS[name] = { f:0, A:0, speed:0 }` and the player is reached from `_loopPose` through the same wrap-the-prototype pattern cast.js already uses for `EXTRA_LOOPS` (chained, falls through to the original for every other name). Time = `T mod cycle`.
- **Name clash**: if `ONESHOT[name]` / `LOOPS[name]` / a `_name` method already exists, `registerTic` does nothing and returns `false` (code tic wins) **unless** `?jsontics` is in the URL, in which case it overwrites. Order matters: cast.js registers code tics at import, `loadTics()` runs after, so the guard is a plain "already defined?" check. The editor itself always previews its draft under a private name (`_draft`) so it never clashes.
- JSON player state: `this.jt = { fired:Set, propsDone:Set }` reset in `play()`; since I must not edit `play`, cast.js's existing pattern is used: wrap `play` once (`this.thrown=false` is already reset there; the wrapper also resets `this.jt`). Pure addition, passes through the original.
- Face from keys: the player sets `p.face = name` (new field, see below); `p.expr/mouth` of the base loop stay untouched when a tic has no `face`.

## Faces
- `faceTex(o, eye, mouth)` → `faceTex(o, f)` where `f = { eyes, brows, mouth, extra }`; cache key = all four parts (+ existing `o.*` bits + override flags). The two existing call sites (`makeChibi` initial, `_apply`) are updated; `critters.js` doesn't use it.
- Compat: the old `p.expr` / `p.mouth` values map to parts (`normal/blink/happy/squint/><` → eyes, `smile/open/o` → mouth) so all existing poses draw **identically** (the baseline faces are pixel-compared, see checks). New pose field `p.face` (FACE name) wins over them.
- New parts drawn in the same canvas code: eyes `wide` (big white, small pupil), `side` (iris shifted sideways), `half` (lid line over the upper half); brows `up in out one` as a rotation/y-offset of the **character's own brow stroke** (`arc|flat|thin|bold` stays; `one` lifts only the right brow); mouth `wide o line pout wobble grit` (`o` already exists from T10 flap, reused); extra `sweat tear lines` (+ existing `blush redEye redEar` mapped from `o.marks/redEye` and `ch.blushEars`).
- `faces.json`: `{ faces: { ok:{eyes,brows,mouth,extra}, … 10 }, overrides: { "<charId>": { noSmileEyes?, hideEyesWhen?: "goggles", default?: "joy" } } }`. `setFaces(json)` merges into `FACE` (the const is exported and mutated, defaults hard-coded so a failed fetch still works).
- `anim.face(name, sec)`: sets `this.fx = { name, t: sec }`; `update` decrements; while active, the face part set = `FACE[name]` after overrides; at expiry the loop's own face returns. Returns nothing (story.js ignores it). Unknown name → console.warn, no-op. `p.face` from a tic also feeds the same resolver (lower priority than an explicit `anim.face` call).
- **Priority** (high → low): `hitT > 0` → `wet` · `anim.face()` overlay · tic `face` / pose `face` · loop expr/mouth · idle blink · elder `smileEyes`. `anim.talking` still replaces only the mouth part (T10 behaviour kept).
- **Blink-cut**: when the resolved part-set changes and the new key is not already a blink, show eyes=`blink` for ~1 frame (`blinkCut = 0.06 s`) before the new set — implemented in `_apply`'s existing face block with a timer; skipped for the first frame of a character and for `hitT` hits (instant is right for a water hit).
- Per-character overrides: Saya Gyi `smileEyes:false` already exists in opts → `joy`'s `happy` eyes become `normal` for him (mouth keeps `wide`); Thura with goggles down (`ch.gogglesUp === false`) draws brows + mouth only; U Tin Maung default face = `joy` when no pose face is set (the idle face, not a forced overlay).

## Editor (`cast.html?edit[&tic=name][&c=ngazwe]`, `editor.js`)
Three-pane as in the spec: left (character picker of 13, tic list code/JSON, + new, kind/duration/cycle/still), centre (existing cast.html canvas + orbit, ghost of previous key = a second cloned rig at 35 % opacity posed with the previous key's pose, transport play/pause/scrub/loop/×.25–×1), right (slider groups for every `KEYS` entry with mirror L↔R and reset-to-base, face picker, prop row, emit row), timeline under the canvas (dots, drag, dbl-click add, delete, copy/paste, ease dropdown). A second tab **Faces**: 4 dropdowns, a 13-character grid showing the current face on everyone, a "10 faces × 13" contact sheet for the screenshot, 「Save faces.json」.
- The editor drives the rig with the **same player function** the game uses (it calls `registerTic` on its draft and plays it through `anim.play('_draft')`), so what it shows is what the game plays; scrubbing sets `anim.oneT` and calls `update(0)`.
- **Save** (no server): 「Copy JSON」, 「Download tics/<name>.json」 (Blob + `<a download>`), autosave draft to `localStorage['tic:<name>']` in try/catch; reload restores the draft. `?edit&tic=name` fetches `tics/name.json` (or the draft) and opens it. The file is committed by hand; `tics/index.json` is listed in the README as a manual line to add.
- Desktop only; `editor.js` is loaded only with `?edit`, everything it adds to the page is created in JS, so the plain roster page DOM is unchanged.

## Risks
- `faceTex` refactor can shift a pixel on existing faces → check 2 is mandatory before anything else.
- cast.js wraps `play` and `_loopPose` (prototype chaining) — order of wraps with T10/T5b-1 additions in the same file; rebase conflicts likely in cast.js, kept small by putting all of it in one block at the end.
- Per-channel sparse interpolation + base-loop layering differ from the code tics' `bell()` shapes (they use smoothed envelopes) → "within one frame" may need extra keys; migrated tics may use 5–6 keys.
- Scrub in the editor must not retrigger emit/props twice (the `jt` sets are rebuilt on scrub backwards).
- Headless 1 fps swiftshader: editor tests wait on game time (`anim.T`), not wall time.
